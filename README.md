## 一、项目简介

“混元智投” 是一个面向全球资产研究场景的 AI Financial Research Agent。  
项目目标是为用户提供基于真实数据、结构化分析和风险提示的研究能力，帮助用户更高效地理解市场、研究公司、跟踪资产与识别风险。

本项目基于以下技术栈构建：

- Tencent 混元大模型
- MCP（Model Context Protocol）
- Agent Workflow
- Next.js
- postgresql

系统核心定位不是做自动交易、收益承诺或喊单工具，而是构建一套可扩展、可落地、可合规的：

# AI Financial Research Infrastructure

即：

- 用 AI 组织金融数据
- 用 Agent 编排研究流程
- 用结构化页面承载研究结果
- 用统一工作流支持未来扩展股票、ETF、基金、期货、宏观和数字货币研究

## 二、产品定位

### 2.1 产品定义

混元智投是一款 AI 驱动的金融研究助手，面向全球市场提供：

- 市场数据解读
- 财报分析
- 基本面分析
- 技术面分析
- 宏观分析
- 风险识别
- 市场情绪观察
- 公司研究与报告生成

它服务的是“研究”和“分析”场景，而不是“承诺收益”或“替代投资决策”。

### 2.2 产品目标

本产品的核心目标是帮助用户：

- 理解市场发生了什么
- 理解某个资产为什么波动
- 理解某家公司基本面是否变化
- 理解宏观变量如何影响资产
- 理解当前风险来自哪里
- 快速获得结构化研究结论

### 2.3 非目标（明确不做）

本项目**不做**以下能力：

- 不保证收益
- 不输出确定性涨跌预测
- 不推荐“买入 / 卖出 / 梭哈”
- 不输出“必涨 / 稳赚 / 翻倍 / 无风险”等表述
- 不替代持牌投资顾问
- 不直接提供自动交易执行能力
- 不做高频交易终端
- 不做喊单型投顾产品

## 四、核心产品原则

### 4.1 研究优先

所有页面与功能都应围绕“研究任务”设计，而不是围绕“情绪刺激”设计。

### 4.2 数据驱动

结论必须尽可能基于真实市场数据、财务数据、宏观数据、新闻事件与技术指标生成。

### 4.3 风险优先

所有分析必须显式给出风险因素，不能只讲利好，不讲风险。

### 4.4 结构化输出

AI 输出必须适合渲染为：

- 标题分区
- 指标卡片
- 图表
- 标签
- 摘要
- 时间线
- 风险列表

### 4.5 合规优先

产品是研究工具，不是收益承诺工具。  
设计、文案、交互、结论必须服从合规边界。

## 十五、Prompt 设计原则

系统 Prompt 必须强调：

- 你是 AI 金融研究 Agent，不是交易顾问
- 回答必须数据驱动、结构化、专业客观
- 必须区分客观事实、分析判断、推测、风险提示
- 涉及金融问题时优先调用真实数据
- 禁止编造数据
- 禁止保证收益
- 禁止制造 FOMO
- 禁止输出确定性涨跌预测
- 每次结论必须附加合规声明

## 十七、开发边界

为避免自动编码工具偏离方向，必须遵守以下边界。

### 17.1 产品边界

- 产品是研究助手，不是交易终端
- 不实现自动下单
- 不实现收益承诺文案
- 不实现“买点 / 卖点信号灯”型高风险功能
- 不使用带强诱导性的营销 UI

### 17.2 页面边界

- 页面核心是研究结构，不是资讯堆砌
- 优先使用卡片、图表、报告视图
- 不做过于花哨的金融营销风
- 不做高噪音红绿闪烁式交易界面

### 17.3 AI 边界

- AI 输出必须可解释
- AI 输出必须带风险提示
- AI 输出必须支持结构化渲染
- 不允许直接把长文本原样堆在页面
- 不允许用 AI 代替真实行情数据

### 17.4 工程边界

- 所有外部数据源必须通过服务层统一封装
- 不允许把第三方 API 逻辑散落在页面组件中
- 页面组件不直接拼接复杂业务逻辑
- 数据结构要预留未来扩展字段
- 所有资产类型尽量使用统一 schema 设计思想

## 十八、UI / UX 设计方向

### 18.1 风格关键词

- 专业
- 克制
- 冷静
- 数据感
- 金融研究风
- 深色优先

### 18.2 视觉建议

- 主色建议：深蓝、灰黑、中性白
- 辅助色建议：绿色用于正向变化、红色用于负向变化，但避免刺激性过强
- 图表优先清晰度，不要过度装饰
- 卡片布局统一，强调信息层次
- 所有重要数据都应可视化或标签化

### 18.3 交互建议

- 搜索优先
- 研究页优先
- 报告沉淀优先
- 支持继续追问
- 支持快速加入自选
- 支持从首页快速跳转到研究对象页

## 十九、开发约束

### 19.1 前端约束

- 使用 Next.js App Router
- 全量使用 TypeScript
- 优先 Server Components + 必要时 Client Components
- 默认支持响应式
- 默认支持深色模式
- 组件尽量通用复用

### 19.2 数据约束

- 所有市场 / 财务 / 新闻 / 宏观 / 链上数据统一封装
- 所有数据请求需要错误处理与降级方案
- 应尽量引入缓存层减少重复请求
- 所有外部接口失败时，页面需要可恢复

### 19.3 AI 约束

- AI 输出统一 Markdown 或结构化 JSON
- 输出必须能被前端渲染成卡片 / 报告模块
- 不允许页面直接展示未经处理的大段模型原文
- 必须保留“事实 / 分析 / 风险”分层

### 19.4 工程约束

- 按模块拆分目录
- 环境变量统一管理
- API Route、服务层、UI 层解耦
- 预留未来扩展更多 MCP Tools 的能力
- 优先保证类型安全
